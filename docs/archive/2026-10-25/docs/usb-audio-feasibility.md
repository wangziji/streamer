# USB 音频接口可行性调查

状态：资料调查，2026-10-22；尚未实机验证或批准器件选型。

## 官方依据

XMOS USB Audio 参考软件支持 UAC1/UAC2、异步 USB、I²S/TDM 和 DSD。公开设计指南列出的参考方案采样率上限为 384kHz，并说明具体功能组合与硬件有关。因此，不能由 XU316 型号或某商品板宣传推定本项目已具备 PCM 768kHz/DSD512。参考固件、编译配置、授权和 Android/电脑主机支持均需核对。

来源：[XMOS 设计指南](https://www.xmos.com/file/sw_usb_audio-sw_usb_audio-design-guide)、[参考软件概述](https://www.xmos.com/documentation/XM-008854-UG/html/doc/rst/overview.html)。

XMOS 默认参考结构由 xcore 提供 I²S 时钟；外部 DAC 的时钟角色及频率必须与配置一致。异步 USB 不等于电气隔离，也不能直接证明整机低抖动或低噪声。

来源：[XMOS Audio Hub 与 I²S](https://www.xmos.com/documentation/XM-012296-UG/html/doc/rst/sw_audio.html)、[USB 与多通道音频介绍](https://www.xmos.com/usb-multichannel-audio/)。

## 本项目候选结构（工程提案）

### A：一个 USB 音频接收器，选择内置主控或外部电脑

Android 主控与外部电脑轮流连接同一个 UAC2 设备，复用后端时钟、数字处理和 DAC。切换通过专门的 USB 路径和供电检测设计实现，禁止将两个主机端直接并联。需要处理 USB 重新枚举、VBUS 回灌、音源优先级和静音时序；连接器和切换器型号待选。推荐作为首版架构候选。

### B：分别接收，再切换数字音频

Android 和电脑各用独立接收路径，由数字音频选择电路连接 DAC。可减少主机端重枚举耦合，但新增接收器、时钟域切换和互锁。需要明确哪些时钟一起切换，不能只切换 DATA。

### C：Android GPIO I²S，外部电脑单独 USB 接收

减少内置播放路径的 USB 环节，但依赖板级 Android 驱动和时钟模式，仍需接收外部 USB 并切换数字音频。不能假设 Linux 驱动或 GPIO 引出代表相应 Android 镜像已支持。

## 共同控制原则（待设计评审）

- 独立控制 MCU 作为整机音量、静音及音源选择的权威；Android 和 USB 主机仅提交请求。
- 所有音源共用输出音量上限与恢复策略，电脑连接不能绕过保护。
- 默认输出静音，电源及音频状态满足条件后才开放输出；关机或切源先静音。
- 心跳监测只是检测手段之一，不能替代硬件默认状态、欠压检测、复位状态及实际故障注入验证。
- 数字音量、模拟衰减或混合方案需依据低音量噪声、声道一致性、失真和故障行为比较后选定。

## 必须通过的实机检查

Android 各目标应用与电脑分别测试：枚举、格式协商、实际输出采样率、音量行为、静音、拔插、热重启、重枚举、无音频与故障恢复。逐项验证目标格式，不能用 DAC 芯片上限替代。高规格固件及格式若无可复现证据，标记为未验证。
