# Android 主控、音源与台架验证包

日期：2026-10-23。状态：待执行方案；全部音源能力仍未验证。本文件不代表主板、容量、屏幕、软件或 USB 选源器件已选定，也不替代模拟音频验收。

## 候选边界与依据

- 主控候选为 Raspberry Pi 5；RAM 和系统存储容量均不冻结。先用可用候选配置测量系统、App、音乐库、缓存及更新空间，再定容量；排除机内音乐 SSD 不等于系统不需要持久存储。
- 7 寸触屏为候选尺寸，不选型号；HDMI+USB 触控与 DSI 两种接口路径分别核查 Android 镜像支持，不能以屏幕物理可连接推定驱动可用。面板、控制板、排线和安装包络均需实物测量后进入机壳设计。
- 主电路依据仅限本地已验证的官方资料。`specs/raspberrypi/raspberry-pi-5-product-brief.pdf`（第3页）、`power-supplies.adoc` 和 `manifest.json` 可用于其覆盖范围内的成品主板集成；RP1 外设参考和产品简介不能替代完整芯片电气规范。本计划不新增芯片级供电或接口电路。
- 软件背景参见 `android-platform-feasibility.md`；音源范围参见 `reference-source-matrix.md`。Android/AOSP 或镜像维护者材料仅作软件可行性依据，不作电路设计依据。镜像版本与功能需要执行时重新核实，不能沿用调查文档中的版本就声称实测通过。

## 交付证据与状态

每次台架运行建立独立记录，至少包含：主板型号/容量、镜像与工具版本和SHA256、内核/安全补丁、显示接口、USB接收器固件、供电/散热配置、App版本与包名、测试时间和结论。测试曲目记录格式与文件摘要；账户只记服务区域、订阅类型和是否具备权限，不保存账号、Cookie、令牌或完整认证日志。

结论统一为“未验证 / 通过 / 失败 / 依赖外部条件 / 范围外”。订阅、区域或认证缺失应注明具体前提，不能记通过；另一 App 或协议的成功不得自动覆盖失败项。所有下列退出条件均为本验证包提案，执行前纳入获批测试基线。

## 执行顺序与退出条件

### P0：建立可复现台架

1. 记录候选 Pi5 容量与启动介质；根据维护者说明确认镜像校验摘要及许可适用范围，不下载来源不明镜像。记录显示、触控、USB DAC 与线材型号。
2. 首轮使用完整成品主板、合规电源和现成 USB DAC 建链路。按本地官方供电章节检查连接外置硬盘、触控与DAC后的供电预算，避免USB回灌；本阶段不试接未经审核的电源电路。
3. Android启动后用只读查询记录版本和基线，例如 `adb shell getprop ro.build.fingerprint`、`adb shell getprop ro.build.version.security_patch`、`adb shell df -k /data`、`adb shell cat /proc/meminfo`。ADB仅在受控台架使用，输出脱敏；命令受镜像权限限制时记录缺失，不擅自root或刷机。

退出条件：版本、文件摘要、硬件连接与供电资料完整，系统稳定启动、显示触控可操作、USB DAC可枚举。未通过则不开始音源验收。

### P1：软件体积、容量与人机操作

1. 分阶段测量“原始系统—安装全部目标App—登录并建库—使用缓存—系统升级”的镜像压缩/展开大小、`/data`已用/可用空间；记录App安装、数据和缓存大小，不能以APK下载大小代替安装后占用。
2. 以实际预期曲目数量构建NAS/USB音乐库，记录曲目数、封面/索引占用、扫描时间和扫描期间RAM峰值；运行播放、浏览大库和手机控制，记录后台App被回收及界面停顿。
3. 候选7寸屏验证横屏、分辨率/DPI、触控校准、App布局、息屏唤醒、冷启动和恢复界面。实体旋钮的音量和静音应与屏幕显示一致，安全关机入口不依赖当前音乐App正常运行。

退出条件：全部必需软件和实际规模音乐库可用，更新与缓存有明确空间余量，资源峰值及操作表现有记录。容量余量阈值、启动/操作时限须在冻结配置前明确；未明确或未测量时不得以“够用”冻结RAM/存储。屏幕驱动和安装包络通过后才选定型号。

### P2：逐音源与接入方式验证

服务场景A：安装/登录、搜索/浏览、首次播放、连续播放、切歌/暂停/恢复、App退出重进、断网恢复；记录源格式与实际输出。网络场景N：发现及手动连接、鉴权、库扫描、文件播放、服务重启和重连。投放场景C：手机/服务器发现、接收角色、队列接管、手机离线后的行为、重新连接；另核认证/授权。存储场景L：记录文件系统、挂载、标签/封面、扫描、热插拔和只读/异常恢复。各场景都独立记录手机控制能力。

### P3：实际数字音频路径

1. 现成DAC阶段用本地已知测试文件覆盖44.1/48/88.2/96/176.4/192kHz及目标位深；352.8/384/705.6/768kHz和DSD高规格另列能力，分别记录文件解码、USB传输和接收结果。
2. 在权限允许时记录 `adb shell dumpsys media.audio_flinger`、`adb shell dumpsys media.audio_policy` 等路由信息；命令或服务名随系统核对。结合DAC状态与必要数字捕获，记录是否有重采样、音量缩放或效果处理。
3. 本地文件、每个服务App和每种接收协议分别验证；测试通知、并发App、插拔与格式切换。DAC显示采样率不构成逐比特保真证据。
4. DSD允许转PCM；明确显示原文件、转换和实际输出格式。只有经端到端验证才能声明原生DSD/bit-perfect；若采用USB BIT_PERFECT，须确认AIDL HAL及策略支持且不依赖Android软件缩放控制纯后级音量。

退出条件：所有必选音源的实际音频路径可解释，异常不会绕过受限音量/静音；测试能力不足的保真结论维持未验证。芯片最高规格不能补足未通过的整机链路。

### P4：USB选源与电脑独立运行

以下为推荐行为合同，供整机方案审核，不是已经实现的能力。选源电路、独立控制器及供电由获批电路方案决定，两个host不可直接并联。

| 工作状态 | 屏幕/手机推荐行为 | 必测动作 |
| --- | --- | --- |
| Android开机、内部播放 | 显示内部输入与统一音量；网页提供基本整机控制 | 旋钮、屏幕、网页同时操作，检查状态一致 |
| Android开机、外部PC输入 | 屏幕明确“外部USB”；网页仍可调整机音量/静音和请求选源，不把PC歌曲控制伪装成本机功能 | PC播放时通知/App不得混入；切换先静音、重新枚举/锁定后恢复受限音量 |
| Android关机、外部PC独立播放 | 依赖Pi的屏幕/网页不可用，应如实显示离线；实体音量、静音、输入选择与保护仍须独立可用 | 保持PC播放，正常关Pi；确认音频可控及无突发满幅；再启动Pi不得抢占输入 |
| Android异常/重启、PC输入 | 屏幕允许不可用，不伪报当前状态；独立音频控制不失效，保护按合同进入安全状态 | 杀死UI/控制服务、重启Pi、断开控制通道；记录静音、恢复及是否需用户确认 |

外部PC模式的独立运行指Pi不工作时DAC子系统仍有设计允许的电源，不代表整机断电还可播放。是否让Pi关机后手机仍能控制，需要独立联网控制端，属于额外架构范围，不能默认获得。

退出条件：内部/外部两种USB主机在隔离、枚举、切换和供电状态组合下均通过；Pi正常关机不使PC模式失去实体控制。若保护策略要求Pi异常时静音，需证明其与独立模式正常运行的判定边界，不能一面宣称独立运行、一面把无Pi心跳一律当故障。

### P5：手机控制与稳定性

推荐首版使用局域网网页提供整机状态、受限音量、静音、输入选择和安全关机请求；仅监听获批局域网并配置访问控制，不默认开放公网。网页若由Pi提供，Pi关机即离线。每个命令需明确成功/失败及实际设备状态，不能只回显点击值。

“基本整机控制”与“任意App远控”分别验收：跨App播放/暂停、选曲、搜索、封面和队列可能需要媒体会话、App接口或该服务的Connect能力。NAS文件可读取不意味着统一手机音乐库已实现，App能播放也不意味着网页能控制其队列。首版不承诺屏幕镜像、自动化点击或通用远程桌面替代正式服务接入。

步骤：逐App列出可远控功能；测试手机浏览器重连、息屏、局域网断开、两个客户端并发和错误输入；验证音量上限不可绕过。选定本地/NAS、流媒体及外部PC路径分别进行24小时稳定性运行，记录温度、内存/存储变化、掉音、异常重启和音量事件，不能只用一个音源24小时代表全部路径。

退出条件：基本网页控制与实体状态一致、失败可见；不支持的App远控明确列出；关键路径无崩溃、非预期中断或越限音量。该结果只解除平台验证门禁，不能替代 `audio-acceptance.md` 的模拟指标、低音量及保护测量。
